# Использование скиллов

<EXTREMELY-IMPORTANT>
Если есть хотя бы 1% шанс что скилл применим к тому что ты делаешь — ты ОБЯЗАН его вызвать.

ЕСЛИ СКИЛЛ ПРИМЕНИМ К ЗАДАЧЕ — У ТЕБЯ НЕТ ВЫБОРА. ТЫ ОБЯЗАН ЕГО ИСПОЛЬЗОВАТЬ.

Это не обсуждается. Это не опционально. Ты не можешь рационализировать отказ от этого.
</EXTREMELY-IMPORTANT>

## Приоритет инструкций

Скиллы переопределяют поведение по умолчанию, но **инструкции пользователя всегда в приоритете**:

1. **Явные инструкции пользователя** (CLAUDE.md, прямые запросы) — высший приоритет
2. **Скиллы** — переопределяют поведение по умолчанию там где конфликтуют
3. **Поведение по умолчанию** — низший приоритет

## Правило

**Вызывай подходящие скиллы ДО любого ответа или действия.** Даже 1% шанс что скилл может быть применим означает что нужно его вызвать. Если вызванный скилл оказался неподходящим — можно не следовать ему.

См. [references/skill-flow.md](references/skill-flow.md)

## Карта скиллов

Базовый набор шаблонных скиллов:

| Ситуация | Скилл |
|----------|-------|
| Пользователь описывает идею / хочет что-то создать или изменить | **write-spec** |
| Есть спек или чёткие требования для многошагового задания | **write-plan** |
| Есть готовый план для выполнения | **execute-plan** |
| Любая ошибка, неожиданное поведение, баг | **debugging** |
| Написать тесты для нового функционала | **write-test** |
| Ревью изменений на качество и безопасность | **code-review** |
| Обновить или почистить CLAUDE.md | **update-claude-md** |
| Подготовить промпт для перехода к следующему этапу в новом чате | **next-stage-prompt** |
| Вопрос, объяснение, консультация — без создания или изменения чего-либо | **скилл не нужен, отвечай напрямую** |

> Проектные скиллы (специфичные для конкретного стека/инфраструктуры проекта) добавляй в эту таблицу отдельной строкой.

## Обязательный порядок работы над фичей

```
write-spec → [спек сохранён в ai/<TASK-ID>/spec.md] → write-plan → execute-plan (с вызовом скилла write-test для написания тестов и скилла code-review для ревью)
```

<HARD-RULES>

1. **Спек обязателен.** write-spec ВСЕГДА завершается записью спека в `ai/<TASK-ID>/spec.md`. Одобрение пользователя требуется только для дизайна (в диалоге write-spec); записанный спек отдельно на одобрение не выносится. Переход к write-plan без спека — запрещён.

2. **Тесты — только через write-test.** Никогда не пиши тесты вручную. После реализации кода вызывай скилл `write-test` через Agent tool (subagent_type не указывай — general-purpose справится). Передавай полный контекст: какой файл изменён, что нужно покрыть.

3. **Ревью — только через code-review.** После завершения реализации (включая тесты) вызывай скилл `code-review` через Agent tool.

4. **Порядок нарушать нельзя.** Нельзя пропускать шаги даже если задача кажется простой.

</HARD-RULES>

## Приоритет скиллов

Когда могут применяться несколько скиллов:

1. **Сначала процессные скиллы** (write-spec, debugging) — определяют КАК подходить к задаче
2. **Потом скиллы реализации** (write-plan, execute-plan, проектные скиллы) — направляют выполнение

Примеры:
- «Хочу добавить новый эндпоинт» → write-spec → спек → write-plan → execute-plan (использует write-test + code-review)
- «Это не работает» → debugging
- «Напиши тесты для нового обработчика» → write-test

## Типы скиллов

**Жёсткие** (debugging, verification-before-completion): следуй точно. Не адаптируй дисциплину.

**Гибкие** (write-spec, write-plan): адаптируй принципы к контексту.

Сам скилл указывает к какому типу относится.

## Красные флаги

Эти мысли означают СТОП — ты рационализируешь:

| Мысль | Реальность |
|-------|------------|
| «Это просто вопрос» | Вопросы — это задачи. Проверь скиллы. |
| «Нужно сначала больше контекста» | Проверка скиллов идёт ДО уточняющих вопросов. |
| «Давай быстро гляну файлы» | Скиллы говорят КАК исследовать. Сначала проверь. |
| «Это не требует формального скилла» | Если скилл существует — используй его. |
| «Помню этот скилл» | Скиллы меняются. Прочитай актуальную версию. |
| «Сделаю эту одну вещь сначала» | Проверяй ДО любого действия. |
| «Скилл избыточен здесь» | Простые вещи усложняются. Используй его. |
