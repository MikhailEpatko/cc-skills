# Пример: сбор доказательств по слоям

Для сбора доказательств в многокомпонентной системе — фиксируй что входит и выходит на каждой границе компонентов.

Подставь команды своего стека (из `CLAUDE.md`). Примеры для разных стеков:

```bash
# Запустить конкретный упавший тест / группу тестов
./gradlew test --tests "com.example.orders.*"      # Gradle
mvn test -Dtest='OrderServiceTest'                 # Maven
npx vitest run src/orders                          # Vitest
npx jest src/orders/create-order.test.ts           # Jest
pytest tests/orders -k "create_order" -x -vv       # pytest
go test ./internal/orders/... -run TestCreateOrder -v
cargo test orders::create -- --nocapture

# Архитектурные тесты, если они вынесены в отдельную задачу
<команда из CLAUDE.md>

# Линтинг / статический анализ
<команда из CLAUDE.md>
```

Дальше — для каждого следующего слоя добавляй проверки выходов компонента: логи, состояние БД, ответ сервиса, содержимое очереди и т.д.

## Слой базы данных

Состояние БД проверяй через инструмент доступа к БД, указанный в `CLAUDE.md` (например, MCP-сервер БД), а не по догадке. Что обычно нужно:

| Что нужно | Чем проверить |
|-----------|---------------|
| Схема, колонки, индексы, ограничения | инструмент получения схемы / `information_schema` |
| Реальные данные | произвольный `select` |
| Количество строк в таблице | `select count(*)` |
| План запроса при разборе производительности | `explain` / `explain analyze` |
