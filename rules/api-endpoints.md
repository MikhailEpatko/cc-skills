## Передача параметров в HTTP-эндпоинтах

- Не используй path variable ни в одном эндпоинте. Параметры не должны быть частью пути URL.
- Для `POST` и `PUT` все параметры передавай в теле запроса (JSON body) через request-модель.
  - Неправильно: `POST /api/catalog/accounts/{accountId}/attributes`
  - Правильно: `POST /api/catalog/accounts/attributes` с `accountId` в теле запроса.
- Для `GET` и `DELETE` все параметры передавай как query-параметры.
  - Неправильно: `GET /api/catalog/accounts/{accountId}/attributes`
  - Правильно: `GET /api/catalog/accounts/attributes?accountId=123`
- Причина: путь URL остаётся стабильным и не зависит от набора параметров, добавление нового параметра не порождает новый вариант пути и не ломает существующий контракт.
- Путь эндпоинта описывает только ресурс и операцию; идентификаторы, фильтры и признаки в путь не выносятся.
- Правило не отменяет остальных требований к параметрам (см. `code-style.md`): все входящие данные необязательны, коллекции в request-моделях — множества, валидация выполняется в `Validate*`-классах.
